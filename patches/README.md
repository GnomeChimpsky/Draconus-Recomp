# Engine patches

`setup.ps1` fetches `dream-recomp` at a pinned commit. This directory holds the project's delta
against that commit, so a fresh clone builds the same engine this project was developed on.

| Patch | What it carries |
|---|---|
| `0001-engine-local-changes.patch` | The sum of ledger entries 001–035 in `docs/ENGINE-CHANGES.md`: the diagnostics and instruction tracer, the hook-dispatch fix, the replay host-state skip, the SR-write rule, the exception-handler stop address (the translated-path fault), the flash side-effect marking, the inlined RAM fast path, cached host memory for the offscreen readback, hor+ widescreen, presentation decoupled from the 60 Hz logic, 4:3 pillarboxing for flat 2D screens (`frame_uses_depth`, plus the presenter's bar discard), the window following `--scale` with `--fullscreen` and a content aspect (`window_size`, `content_aspect`), `--present-rate` capped to the display's refresh (`present_rate`), geometry interpolation for the extra presents (`interpolate`), the per-user memory card a windowed run attaches when `--vmu` names none (`default_vmu_path`), windowed/borderless/exclusive display modes (`DisplayMode`), the screen-space HUD compression that keeps the HUD's 4:3 shape at 16:9 (`compress_screen_overlays`), the direct-present path that keeps a finished frame on the GPU for the presenter to sample (`Presenter::use_image`, `Offscreen::read_back`), the overlay's blend destination supplied separately as `under` so the frame counter and the binding screen stop reading the write-combined staging buffer (`fill_rect`, `draw_text`, `Presenter::upload`'s `decorate`, `InputMenu::draw`), exclusive fullscreen choosing a refresh that is a whole multiple of the picture rate so every picture is held for the same number of vertical blanks (`Window::set_content_hz`), a runtime SH-4 clock so a scene that misses its real budget can be given more cycles per blank (`--sh4-clock`, `sched::sh4_clock`), and the jump pack in the controller's second expansion slot whose effects drive ordinary gamepad rumble (`maple::JumpPack`, `Window::rumble`), with the frame-time, presentation-cadence, per-frame and host-profile diagnostics (`DREAM_TRACE_FRAME_HIST`, `DREAM_TRACE_PACING`, `DREAM_TRACE_FRAMES`, `DREAM_PROFILE`, `tools/profile-map.py`, `DREAM_MAPLE_TRACE`, `DREAM_RUMBLE_TRACE`), the HUD-panel pass that carries the item wheel's 3D models with the wheel and refuses a world-space particle billboard (`compress_screen_overlays` panel rule), `dream_render_view --aspect` for checking a capture at a widescreen aspect, and the launcher's audio device/volume/buffer controls (`--audio-device`, `--audio-volume`, `--audio-buffer`, `--list-audio-devices`). Touches `runtime/`, `translator/`, `render/`, `audio/` and `cmake/`. |
| `0002-modern-controls.patch` | Ledger entry 036: the optional `--controls modern` layer — `InputPreset`/`effective_bindings`, extra physical sources for A and X, `Window::set_input_preset`, and the XInput remap. The launcher **Controls** option, `-ModernControls` and the input tests accompany it in the repository. |
| `0003-m5-coverage.patch` | Ledger entries 037–038: pointer discovery scans far enough to reach Draconus's long static-constructor functions (200 → 1,024 instructions; 8,936 → 9,126 functions), and `resume_miss` retries the other functions containing an address before the interpreter. Together they take a 60 s scripted play from 101 untranslated calls to 0. |
| `0004-frame-interpolation-pairing.patch` | Ledger entry 039: the interpolation stops tearing the picture. The resynchronisation window goes from two candidates to sixteen, a strip whose list position changed is paired on its texture coordinates, and every corner is moved by *position* rather than by strip so two strips that share one cannot move it differently (the seams that opened and snapped shut). The presenter repeats the current picture for a still frame or one whose pairing mostly failed, presents the intermediate frame from the GPU instead of round-tripping it through the host, and F11 captures the picture that is actually on screen (with a `.interp` geometry dump when that is the intermediate frame). The on-screen counter is drawn on the GPU as solid rectangles from the same font geometry (`shaders/overlay.*`, `overlay::text_rects`), so it no longer reads the frame back on every present. Touches `render/{include,src,shaders,tests}` and `runtime/boot/boot_main.cpp`; adds `DREAM_INTERP_PAIR` and a frame list for `DREAM_INTERP_DUMP`. The launcher's present-rate list comes from the display's own modes, in the repository rather than in this patch. |
| `0005-boot-from-disc.patch` | Ledger entry 040: a release ships no extracted `1ST_READ.BIN`, so the runtime reads the boot program from the player's own disc when `[binary] path` is absent. `[disc] boot_lba`/`boot_size` give the location, `Disc::read_user` reads the sectors (GDI and CHD), and the bytes are checked against `sha1_1st_read` before use; `--disc FILE` overrides `[disc] image`. Touches `runtime/boot/boot_main.cpp`, the new `runtime/include/dream/runtime/hash/sha1.h`, `translator/{include,src}/…/game_config.*`, the config tests and `docs/game-config.md`. |
| `0006-utf8-paths.patch` | Ledger entry 041: Windows hands the process UTF-16 arguments, but the runtime used narrow `argv` and ANSI `ifstream`/`fopen`, so a non-ASCII user name or disc path was silently mangled. `wmain` converts the arguments to UTF-8 once; config-relative paths use `std::filesystem::u8path`; the GDI, CHD and CDI readers open native wide paths (`_wfopen`, `chd_open_file`); the VMU and bindings filesystem paths are `std::filesystem::path`; debug outputs go through a UTF-8 `fopen`. Touches `runtime/boot/boot_main.cpp`, `runtime/src/gdrom/disc.cpp`, `runtime/src/maple/maple.cpp`, `runtime/include/dream/runtime/maple/maple.h` and `translator/src/config/game_config.cpp`. |
| `0007-user-data-folder.patch` | Ledger entry 042: the player's bindings move from the nested `<data>/dream-recomp/dream-recomp/` to `<data>/dream-recomp/`, beside the launcher's settings and the saves folder. `default_bindings_path()` asks SDL for an app-named folder with no organisation, so one per-user folder holds everything this project writes. Touches `render/src/vk/window.cpp`. The launcher's settings make the same move in the repository (`tools/launcher.py`), with the old file as a read-only fallback. |
| `0008-present-rate-bound.patch` | Ledger entry 043: `--present-rate` parses with `strtol` and refuses a negative or non-numeric value, and anything above 1000 Hz, instead of casting a wrapped `strtoul` result to `unsigned` and accepting a rate no display can run. Touches `runtime/boot/boot_main.cpp`. |
| `0009-widescreen-overlay-depth.patch` | Ledger entries 044–045: the widescreen overlay pass keeps its HUD panels inside the near-depth slab, moves a panel's projected 3D model with it instead of squeezing it twice, and lets a small marker be compressed with the map image it sits in (the death screen's fade no longer tears, the HUD item model is no longer a quarter too thin, the map's markers stay on the map). And the translucent pass sorts strips by their mean depth rather than their nearest vertex, so a large floor under a character no longer blends over it. Touches `render/{include,src,tests}`. Applies after 0008. |
| `0010-bindings-migration.patch` | A player who rebound controls before the per-user folder move still has the old nested `bindings.txt`; copy it once to the new path so the upgrade does not silently reset the layout. Touches `render/src/vk/window.cpp`. |
| `0011-present-rate-clamp.patch` | The exclusive-fullscreen mode chooser clamps a requested content rate to the desktop refresh, so the mode it picks and the rate the boot presents agree. Touches `render/src/vk/window.cpp`. |
| `0012-hybrid-gpu.patch` | Device choice waits for the window's surface, then tries each candidate that can present to it, so a hybrid-GPU machine does not pick a render-only device. Touches `render/{include,src}/vk/context.*` and the window's creation path. |
| `0013-fov.patch` | Ledger entry 046: `--fov DEG`, a `[camera]` block naming the title's vertical FOV constant (`0x0C098648`, 90°), and the launcher's **Field of view** slider. The projection's aspect (widescreen) and FOV are separate inputs, so the two settings compose. The HUD panel pass also takes the FOV scale, so the item wheel's projected 3D model is scaled back about the panel's centre and raised in front of it instead of being covered by the ring. Touches `translator/{include,src}/…/game_config.*`, `runtime/boot/boot_main.cpp`, `translator/tests/test_config.cpp`, `render/include/dream/render/display_list.h`, `render/src/display_list.cpp`, `render/src/view_main.cpp` and `render/tests/test_display_list.cpp`; the title TOML and launcher live in this repository. Applies after 0012. |
| `0014-look-offset.patch` | Ledger entry 047: the soft right-stick look. The projected 3D vertices are turned back into camera rays from screen x/y and `1/w`, pitched about the camera's horizontal axis and reprojected; screen-space HUD and the item wheel's panel contents stay put. Adds `render/include/dream/render/camera_look.h`, `render/src/camera_look.cpp` and `render/tests/test_camera_look.cpp`, and touches `render/CMakeLists.txt`, `runtime/boot/boot_main.cpp`, `render/src/view_main.cpp`, `render/include/dream/render/vk/window.h` and `render/src/vk/window.cpp`. `--look` is the fixed capture form, `--look-invert` flips the stick, and the launcher's **Invert right-stick look** lives in this repository. Applies after 0013. |

`setup.ps1` applies each patch after fetching the engine, and is safe to re-run: after a successful
run it writes `engine/.draconus-patches`, and a tree that predates the marker is recognised by the
features each patch adds.

## Refreshing the patch

When the ledger changes, regenerate the file from two trees with the same layout: `a/` a pristine
engine at the pinned commit, `b/` the working engine, both containing the changed source
directories (`audio/`, `cmake/`, `render/`, `runtime/`, `translator/`).

```powershell
# a/ = freshly fetched engine; b/ = the checkout with the changes applied
git diff --no-index --no-renames --no-color --src-prefix= --dst-prefix= a b > 0001-engine-local-changes.patch
```

`0002-modern-controls.patch` is generated the same way, with `a/` the pinned tree **plus 0001** and
`b/` the working engine; it therefore applies after 0001 in `setup.ps1`'s sorted order. Patches 0003
onwards were each generated against the tree with all earlier patches applied, and `setup.ps1` applies
them in name order, so `0007` and `0008` sit on top of `0006` and `0009` on top of `0008`.

Apply a patch with `git apply -p1` from inside `engine/`. Verify before committing:

```powershell
cd engine; git apply --check <repo>\patches\0001-engine-local-changes.patch
```
